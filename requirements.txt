# ---- vLLM: needed for EVAL, and also for TRAINING ----
# The README used to say training does not need vLLM. That is wrong:
# `hyper_llm_modulator.utils` reaches vllm_eval through its import chain, so
# `python -m inlet.train_inlet` fails with ModuleNotFoundError: vllm before it
# reaches a single training step. Verified 2026-08-24.
#
# vllm 0.11.1 ships kernels built against CUDA 12 while torch 2.9.0 here is
# cu13; the upstream env.sh LD_PRELOADs the cu12 cublas/cudart to bridge that.
# scripts/common.sh sources it automatically.
vllm==0.11.1

# evalplus: MUST come from this git commit, NOT from PyPI, and NOT with deps.
#
#   * PyPI evalplus >= 0.3.1 renamed `evalplus.eval.SUCCESS` to `_SUCCESS`, and
#     the vendored fishfarm imports the old public name:
#         ImportError: cannot import name 'SUCCESS' from 'evalplus.eval'.
#         Did you mean: '_SUCCESS'?
#     upstream's uv.lock pins the commit below; match it.
#   * with deps, its resolver moves transformers. Hence --no-deps, which then
#     leaves its own runtime imports missing -- they surface far away, inside
#     `python -m inlet.train_inlet`, as ModuleNotFoundError: tempdir / wget / ...
#     So install those five by hand too.
#
# pip install --no-deps "git+https://github.com/evalplus/evalplus@1895d2f6aa8895044a7cf69defc24bd57695e885"
# pip install --no-deps tempdir wget termcolor multipledispatch appdirs rich
#
# DO NOT add evalplus to this file: `pip install -r` would pull its deps.
# scripts/setup_env.sh installs it separately, with --no-deps. If you are
# installing by hand, run those two commands above verbatim.
# ---------------------------------------------------------------------------
tempdir
wget
termcolor
multipledispatch
appdirs
rich
